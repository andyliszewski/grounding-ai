## Story

**As a** grounding-ai user enabling hybrid retrieval,
**I want** the dense channel to actually return results when hybrid mode is on,
**so that** `--hybrid` fuses BM25 and dense as designed instead of silently degrading to BM25-only (or returning nothing).

---

## Background

All three retrieval surfaces strip the chunk-map wrapper dict on load
(`chunk_map = chunk_map_data["chunks"]`), then the hybrid path re-wraps
the bare list as `{"chunks": chunk_map}` and hands it to `search_hybrid`
via `load_index_fn`. The re-wrapped dict has **no `format_version` key**,
so `search_similar_chunks` (`grounding/vector_store.py:332-336`) defaults
to `"1.0"`, takes the v1.0 branch, looks for an absent `chunk_ids` list
(empty), and skips every FAISS hit with an "Invalid index N returned by
FAISS, skipping" warning.

Reproduced in-memory during the 2026-06-12 review: with the adapted map
the dense channel returns `[]`; with `format_version: "1.2"` present it
returns correct results.

Consequences:
- `hybrid_enabled=true` **with** BM25 artifacts present → results are
  silently **BM25-only** masquerading as fused RRF (every hit has
  `faiss_rank=None`). Semantic-paraphrase recall — the entire reason to
  enable hybrid — collapses to lexical-only.
- `hybrid_enabled=true` **without** BM25 artifacts (pre-19.1 agents) →
  the dense-only degraded fallback iterates an empty list and returns
  **zero results**, rendered to the user as "No relevant documents
  found": a total retrieval failure presented as an empty corpus.
- ~`pool_size` spurious FAISS warnings logged per query.

**Measurement impact:** Story 19.4's four-cell `{hybrid off/on} ×
{rerank off/on}` matrix ran through the CLI hybrid path and is therefore
suspect. The null result it reported may be an artifact of this bug, not
a true saturation finding. TD-004's eventual default-flip decision must
not rely on pre-fix numbers.

## Affected Sites

- `mcp_servers/corpus_search/server.py:96-97, 173`
- `scripts/search_corpus_tool.py:267-272`
- `scripts/local_rag.py:179-180, 248-252`

`format_version`, the load step discards it, and the hybrid adapter
re-wraps without restoring it.

## Acceptance Criteria

1. The hybrid path on all three surfaces passes a chunk-map structure
   that carries the correct `format_version`, so `search_similar_chunks`
   takes the version-appropriate branch and the dense channel returns
   results. Preferred fix: retain the full on-disk dict (do not discard
   `format_version` at load), rather than hard-coding a version string
   in the adapter. If the adapter must re-wrap, it copies
   `format_version` (and any other top-level keys the loader reads) from
   the on-disk dict.
2. With hybrid on and BM25 present, returned results include populated
   `faiss_rank` values for chunks the dense channel ranked — i.e. fusion
   is demonstrably happening, not BM25-only. A test asserts at least one
   result with a non-null `faiss_rank` on a fixture where the dense
   channel should hit.
3. With hybrid on and BM25 **absent**, `search_hybrid` returns dense
   results (not zero) and marks them `hybrid_degraded: True`, matching
   the documented dense-only fallback contract.
4. A regression test exercises the exact load→adapt→`search_hybrid`
   path of the surfaces (not just `search_hybrid` in isolation with a
   hand-built map), so a future reintroduction of the wrapper-stripping
   bug is caught. The test fails against current `main` and passes after
   the fix.
5. The spurious "Invalid index N returned by FAISS, skipping" warnings
   no longer fire on the happy path.
6. The three surfaces stay consistent: the fix is applied uniformly, and
   a shared helper (or a documented shared pattern) prevents the three
   copies from drifting again. If a helper is introduced it lives in
   `grounding/` and is imported by all three.
7. Non-hybrid (dense-only default) behavior is byte-for-bit unchanged.

## Technical Notes

- **Integration approach:** smallest correct change is at the load step
  — stop discarding the wrapper, or thread `format_version` through the
  adapter. Three call sites; one regression test per path or one
  parametrized test across all three.
- **Constraint:** do not change the on-disk artifact format. This is a
  read-path wiring bug, not a format problem. FAISS, `_chunk_map.json`,
  and BM25 files are all correct on disk.
- **Watch for:** the dense-only fallback (BM25 absent) and the
  fused-pool path (BM25 present) are different code branches — AC 2 and
  AC 3 must both be tested.

### Implementation Summary
Root cause confirmed in code: all three surfaces extract the bare `chunks`
list at load (`server.py:94-99`, `local_rag.py:177-182`,
`search_corpus_tool` cached `self.chunk_map`), discarding `format_version`.
The hybrid adapter re-wrapped as `{"chunks": list}`; `search_similar_chunks`
(`vector_store.py:332`) then defaulted `format_version` to `"1.0"`, read the
absent `chunk_ids` list, and skipped every FAISS hit → empty dense channel.

Fix chosen (story AC 1 preferred + AC 6 drift-protection): a single shared
helper `adapt_chunk_map_for_search` in `grounding/vector_store.py`, called by
all three surfaces in place of the inline `{"chunks": ...}` re-wrap. The
helper stamps the metadata `format_version` (1.2) onto a bare list of dict
entries so the dense channel reads `chunks`; passes an already-correct dict
through; and leaves the legacy bare-string-list shape unstamped (no crash on
`str.get`). The dense-only positional paths (`chunk_map[idx]`) are untouched —
the helper only affects the map handed to `search_hybrid`'s `load_index_fn`.

Why a helper rather than "retain the full dict at load": the dense-only paths
index the cached map positionally as a list; returning the full dict from the
loaders would have broken those. The helper is the smaller, drift-proof change
and satisfies AC 6 (one source of truth, imported by all three).

### Key insight on test coverage
The existing hybrid suites (`test_search_corpus_tool_hybrid.py`, etc.) stub
`search_hybrid` wholesale — they never exercise the real
`search_hybrid → _dense_channel → search_similar_chunks` path, which is
exactly why this regression shipped. The new tests deliberately drive the real
path with a fake FAISS index + injected loaders, so the format_version branch
is actually executed (AC 4).
